# 心伴 AI-Pet v3.0.0：实现与验证证据

更新日期：2026-08-12  
固定代码：`v3.0.0` / `87ecf0df3c120d33b1be7e847dafe9792d159b59`

## 证据范围

本文件只报告可以由代码、构建和自动测试直接支持的工件级证据。当前没有未成年人参与者数据（`N = 0`），没有声称改善学生心理健康、提高识别准确率、减少教师工作量或产生干预效果。

适合写入本轮 EITT 论文的问题是：

1. 该双端研究原型能否实现“学生自主记录—可选 AI 短回应—教师最少必要支持线索”的端到端技术路径？
2. 在增加语音输入时，哪些本地优先、数据最小化和人在回路控制可以落实为可检查的软件工件？
3. 原型级场景测试会暴露哪些仍需在学校试点前解决的部署与治理缺口？

这些是设计与技术可行性问题，不是效果问题。

## 已实现能力与证据

| 主张 | 已实现工件 | 可复核证据 | 边界 |
|---|---|---|---|
| 学生自主记录 | 心情、可选文字、小目标、真人支持选择；查看、CSV 导出和删除 | `/api/moods`、学生端记录界面、D1 schema | 参与者代号是化名，不是正式身份认证 |
| AI 默认可选 | “保存记录”为默认主操作；每条记录单独选择 AI；模型回复不另存 | `StudentCompanion.tsx` 的 `wantsAi` 与分离调用 | 心情记录文字本身会保存，界面已明确说明 |
| 短会话与现实连接 | 一次提交只产生一条建议；回应卡提供结束动作与真人支持入口 | Qwen system prompt、回应区与会话收束状态 | 未评估学生实际感受或长期使用行为 |
| 中国模型适配 | Qwen 北京地域严格域名白名单；固定文本与 ASR 快照 | `lib/qwen.ts`、`.env.example` | 当前发布不含真实 API Key，未做厂商在线质量评估 |
| 语音数据最小化 | 30 秒、2.5 MB、格式校验；请求内存转写；不入 D1/R2/日志；文本可编辑 | `/api/voice/transcribe`、`lib/voice.ts`、前端录音状态机 | 浏览器容器解析不是可信媒体网关；Safari MP4/M4A 回退文字 |
| 本地危机优先 | 文本聊天在外部 LLM 前本地拦截；ASR 文本返回后立即本地检查；危机文本不再发聊天模型 | `lib/safety.ts`、chat/voice routes、自动测试 | 关键词规则不能保证识别全部风险，也不等于通知已送达 |
| 原型级接口保护 | 同源检查、Qwen 域名白名单、体积/时长、6 次/分钟、并发 4、短期重放阻断 | `lib/http.ts`、`lib/voice-rate-limit.ts` | 内存限流不跨 Worker 实例；正式环境需平台级持久限流和预算告警 |
| 教师最少披露 | 聚合趋势与匿名支持队列；普通聊天不显示；CCCR 人工核对流程 | `/teacher` 与 `/api/teacher/summary` | 共享教师密钥仅适合原型，没有学校 SSO/MFA/角色审计 |
| 版本隔离 | v1/v2/v3 Git 标签与固定说明页；v3 使用新 Sites 项目和独立 D1 | Git 历史、GitHub Releases、`.openai/hosting.json` | 代码版本保留不等于永久保存学生数据 |

## 自动验证结果

在 Windows 本地构建环境中完成：

- Vinext 生产构建：通过；包含 `/`、`/teacher`、`/api/moods`、`/api/chat`、`/api/teacher/summary`、`/api/voice/transcribe`。
- ESLint：通过。
- SSR/API 自动测试：10/10 通过。

测试覆盖：

1. 学生端 SSR 出现隐私优先保存、可选 AI 和 AI 身份说明。
2. 教师端 SSR 使用脱敏样例且不呈现日常聊天原文。
3. 语音接口拒绝跨源请求和坏数据。
4. 语音接口在外部调用前快速拒绝正常 WAV 容器中超过 30 秒的音频。
5. 解码后体积超过 2.5 MB 时拒绝。
6. 未配置 Qwen ASR 时失败关闭并返回 503。
7. 文本危机规则在已配置 Qwen 的情况下仍保持零外部 LLM 调用。
8. ASR 返回危机文字时立即生成本地真人求助提示。
9. 每客户端原型级语音限流生效。
10. 供应商未返回 `usage.seconds` 时失败关闭。

## 尚未验证，不能写成结果

- 未进行真实 Qwen 文本或语音调用，因此没有转写准确率、延迟、费用、方言覆盖或模型安全质量结果。
- 未进行学生可用性、接受度、情绪调节或福祉效果研究。
- 未进行教师任务时间、判断一致性、误报/漏报或工作量研究。
- 未验证学校危机通知送达、超时升级、假期值守和监护人联络闭环。
- 未完成真实移动设备矩阵、麦克风权限、设备 TTS 声音和中国大陆网络可达性测试。
- 未完成学校伦理审查、监护人同意、学生本人同意、供应商数据处理协议或正式数据保留方案。

可使用“实现、构建、验证、在场景测试中通过/失败”等措辞。不要使用“有效改善、准确识别、显著提升、减少漏报、提高教师效率”等未经参与者或任务实验支持的措辞。网站和自动测试只能作为设计/技术工件证据，不能替代学生或教师研究结果。
