# 心伴 AI-Pet v1.0.0 — 全栈研究原型 / Full-stack Research Prototype

## 中文

v1.0.0 是“心伴 AI-Pet”的首个端到端全栈研究原型，展示“学生自我记录 × AI 低压力回应 × 教师人工支持”的完整技术路径。

### 在线版本

- 学生端：https://xinban-ai-pet-eitt26.nwowxgckhq45.chatgpt.site/
- 教师端：https://xinban-ai-pet-eitt26.nwowxgckhq45.chatgpt.site/teacher
- 固定源码：https://github.com/ling20251121/xinban-ai-pet/tree/v1.0.0
- 源码提交：`4132a13ac4e2795e2c476a72270aff6c6470adfd`

这是保留的历史全栈版本。公开会议或课堂展示建议优先使用 v2.0.0 静态版。

### 已实现

- 学生使用参与者代号记录每日心情、可选文字、小目标和真人支持请求。
- 心情记录通过在线 D1 数据库持久保存，刷新或更换设备后可按同一代号重新读取。
- 学生可查看记录、导出结构化 CSV 摘要，并删除该代号下的全部记录。
- “仅保存记录”和“保存并请小伴回应”分开授权。
- 服务端已适配 DeepSeek、豆包（火山方舟）和 Kimi；每次部署只启用一个经审批的模型供应商。
- 没有配置模型密钥、模型故障或超时时，自动回退到确定性的安全示例回应。
- 外部模型密钥只保存在服务器环境中，不进入浏览器或公开仓库。
- 自伤或即时危险表达先由本地关键词规则处理；命中时不把危机文字发送给外部模型。
- 教师端提供固定脱敏示例，也可在服务器配置访问密钥后查看 D1 实时汇总。
- 实时教师视图包括班级聚合、七日趋势、主动支持请求和需人工确认的支持队列。
- 教师端不展示普通聊天记录；支持队列只显示参与者代号、结构化选择、时间及最少必要证据。

### 数据边界

- D1 会保存参与者代号、参与者代号的加盐摘要、心情、可选文字、小目标、支持选择和安全标记。
- 参与者代号是化名标识，不等于严格匿名；知道同一代号的人可能读取或删除其记录。
- 心情记录中的可选文字会保存；模型对话不会另行保存为聊天记录。
- 危机规则只生成本地提示和教师队列标记，不会自动通知老师、家长、学校、110 或 120。
- 教师实时视图依赖服务器端访问密钥；共享密钥不是正式学校身份认证。
- 本版本没有学校账号体系、MFA、角色权限、访问审计、通知送达确认或正式数据保留策略。

### 重要限制

本版本只适合使用合成或充分脱敏数据进行受控技术演示。它不是心理测评、诊断、治疗或自动转介工具，也未被证明具有干预效果。未经学校伦理与信息安全审批、监护人同意和学生本人知情同意，请勿输入真实未成年人信息。

模型“已适配”不代表公开部署已经启用真实模型；部署者必须自行配置经批准的服务端密钥。仓库和 Release 不包含任何 API Key。

本地关键词规则不能替代专业判断，也不能保证识别所有风险。支持队列只有在真人主动查看后才可能产生后续行动，本版本不具备自动通知、送达确认或超时升级能力。

## English

v1.0.0 is the first end-to-end full-stack research prototype of Xinban AI-Pet. It demonstrates the complete pathway of student self-check-ins, low-pressure AI responses, and teacher-led human support.

### Live version

- Student view: https://xinban-ai-pet-eitt26.nwowxgckhq45.chatgpt.site/
- Teacher view: https://xinban-ai-pet-eitt26.nwowxgckhq45.chatgpt.site/teacher
- Immutable source: https://github.com/ling20251121/xinban-ai-pet/tree/v1.0.0
- Source commit: `4132a13ac4e2795e2c476a72270aff6c6470adfd`

This historic full-stack release is retained for architecture and workflow demonstrations. v2.0.0 is recommended for public conference or classroom presentations.

### Implemented capabilities

- Students use a participant code to record a daily mood, optional note, small goal, and request for human support.
- Check-ins persist in an online D1 database and can be retrieved later with the same code, including from another device.
- Students can review their entries, export a structured CSV summary, and delete all entries associated with their code.
- “Save only” and “save and request a companion response” are separate choices.
- Server-side adapters are implemented for DeepSeek, Doubao through Volcengine Ark, and Kimi. One approved provider can be enabled per deployment.
- If no provider is configured, or a provider fails or times out, the application returns a deterministic safe fallback response.
- Provider credentials remain server-side and are never shipped to the browser or repository.
- Keyword-based local safety screening runs before any external model request. Crisis text is not forwarded to an external provider when a rule is triggered.
- The teacher view includes a fixed de-identified sample and can load live D1 aggregates when a server-side access key is configured.
- Live summaries include class aggregates, seven-day trends, support requests, and a human-review queue.
- Ordinary chat transcripts are not shown to teachers. The queue exposes only a participant code, structured signals, time, and minimal supporting evidence.

### Data boundaries

- D1 stores the participant code, a peppered digest of that code, mood, optional note, goal, support choice, and safety flag.
- A participant code is a pseudonymous identifier, not strict anonymity. Anyone who knows the same code may be able to retrieve or delete its entries.
- Optional check-in text is stored as part of the mood entry; no separate chat transcript is retained.
- A safety flag creates an on-screen response and a teacher-queue item only. It does not automatically notify a teacher, guardian, school, police, or emergency service.
- Live teacher data requires a server-side access key. A shared key is not production-grade school authentication.
- This release does not include school SSO, MFA, role-based access, access auditing, delivery acknowledgement, or a formal retention policy.

### Important limitations

Use only synthetic or properly de-identified data in a controlled technical demonstration. This release is not a psychological assessment, diagnosis, treatment, or automatic referral service, and no intervention effectiveness is claimed. Do not enter real minors’ information without school ethics and security approval, guardian consent, and the student’s informed assent.

“Adapter implemented” does not mean that the public deployment currently uses a live model. An operator must configure an approved server-side key. No API key is included in the repository or this release.

Keyword rules cannot replace professional judgment and cannot guarantee detection of every risk. A queue item can lead to action only after a person actively reviews it. This release has no automatic notification, delivery acknowledgement, or escalation timer.
